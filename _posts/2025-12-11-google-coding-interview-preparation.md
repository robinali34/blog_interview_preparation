# Google Coding Interview Preparation - Top Questions by Category

A comprehensive guide to Google coding interviews, covering LeetCode-style problems, data structures, algorithms, and Google-specific focus areas. This guide categorizes top questions by topic with difficulty ratings and frequency indicators.

## Overview

**Target Audience**: Software engineers preparing for Google coding interviews  
**Company Focus**: Search, cloud computing, AI/ML, distributed systems, mobile (Android)  
**Interview Format**: LeetCode-style coding problems, system design, and computer science fundamentals  
**Difficulty**: Mix of Easy, Medium, and Hard problems (emphasis on Medium-Hard)  
**Interview Duration**: 45 minutes per round, typically 2-3 coding rounds

## Google Interview Characteristics

### What Google Looks For
- **Problem-Solving Skills**: Ability to break down complex problems
- **Algorithm Knowledge**: Deep understanding of algorithms and data structures
- **Code Quality**: Clean, efficient, well-commented code
- **Communication**: Clear explanation of thought process
- **Optimization**: Ability to optimize solutions (time/space complexity)
- **Edge Cases**: Handling edge cases and error scenarios

### Google-Specific Focus Areas
1. **String Manipulation**: Text processing, parsing, pattern matching
2. **Tree & Graph Algorithms**: Traversal, search, dynamic programming on trees
3. **Dynamic Programming**: Optimization problems, memoization
4. **Greedy Algorithms**: Optimization problems with greedy choices
5. **Binary Search**: Search in sorted arrays, search space reduction
6. **Two Pointers**: Array/string manipulation, sliding window
7. **Backtracking**: Constraint satisfaction, combinatorial problems

## Preparation Strategy

- Master basic data structures: Arrays, Strings, Hash Tables
- Learn fundamental algorithms: Sorting, Binary Search
- Practice Easy problems (50-100 problems)

### Phase 2: Core Topics (Weeks 3-4)
- Focus on high-frequency topics: Trees, Graphs, DP, Backtracking
- Practice Medium problems (100-150 problems)
- Master common patterns: Two pointers, sliding window, DFS/BFS

### Phase 3: Advanced Topics (Weeks 5-6)
- Tackle Hard problems
- Focus on optimization and edge cases
- Practice system design concepts

### Phase 4: Mock Interviews (Weeks 7-8)
- Practice with time constraints (45 minutes)
- Mock interviews with peers
- Review and refine solutions

## Interview Tips

### During the Interview

1. **Clarify the Problem**
   - Ask questions about inputs, outputs, constraints
   - Understand edge cases
   - Confirm assumptions

2. **Think Out Loud**
   - Explain your thought process
   - Discuss approach before coding
   - Show your problem-solving skills

3. **Start with Brute Force**
   - Show you can solve it first
   - Then optimize
   - Discuss time/space complexity

4. **Write Clean Code**
   - Use meaningful variable names
   - Add comments for complex logic
   - Handle edge cases

5. **Test Your Solution**
   - Walk through examples
   - Test edge cases
   - Verify correctness

### Common Mistakes to Avoid

1. ❌ **Jumping to code** - Think first, code second
2. ❌ **Not asking questions** - Clarify requirements
3. ❌ **Ignoring edge cases** - Handle null, empty, single element
4. ❌ **Not optimizing** - Discuss time/space complexity
5. ❌ **Not testing** - Verify your solution works
6. ❌ **Giving up** - Show persistence and problem-solving
